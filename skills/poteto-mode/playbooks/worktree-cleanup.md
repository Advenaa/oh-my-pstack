### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` from this skill's folder (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives somewhere else entirely (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, lock state, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or the host's session list and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins. The script's history cross-check is only a warning. No match proves nothing, because the path may be implicit.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan read-only `explorer` children out through the active adapter's **Panel** protocol to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background children, and those are in use even when their names never appear in the host's session list. Set each child's reasoning level for the job through its role configuration, per the Subagents section. Treat missing history as unknown, never as proof of inactivity.
4. Pause on irreversible loss or protection. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. `locked:<reason>` is an intentional Git protection. It always holds, and unlocking it takes a separate explicit decision. Per Autonomy, clean, unlocked, merged, and not-in-use proceeds. `wip`, `locked`, and in-use pause.
5. Prune the confirmed set recoverably. Move each worktree directory to Trash with `trash <path>`, then `git worktree prune`. Do not run `git worktree remove --force`, which can destroy untracked files before Trash sees them. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, the editor's own state directory when a history database or a snapshot root named for a folder you opened as a workspace has ballooned, and package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, locked, or uncommitted work).
